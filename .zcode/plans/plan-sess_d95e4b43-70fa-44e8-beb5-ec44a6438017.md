# 修复删框闪屏/卡顿(验证现状 + fragment 局部刷新)

## 背景
用户在手动标注页点「删」时整页刷新、卡顿。根因两层:
1. 闪屏:旧实现删框换画布 key → iframe+背景图整体重挂载。**已改**为模型驱动 `initial_drawing`(前端 loadFromJSON 原地重画),浏览器已证实 iframe 不再重建;
2. 卡顿:删除仍触发全页 `st.rerun()`,整个脚本(三 tab+GPU 面板)重跑。

## 第 1 步:可靠验证现状(先确认已修的部分)
- 重启服务,开全新浏览器标签(不复用旧 tab,规避内嵌浏览器快照过期问题);
- 验证只用**活 DOM evaluate 查询**(不再依赖 domSnapshot)+ 磁盘真相:
  - iframe 打标记 → 点删 → 标记仍在(无重挂载)、右侧「N 个框」计数减一、删/保存按钮仍可查询到(页面未卡死);
  - 目录模式:画框→删框→保存 → 断言 /tmp/ml_test/labels/*.txt 内容;
  - 审核模式:删框→通过 → 断言 autolabel_work/review_state.json 内容。

## 第 2 步:fragment 局部刷新(根治卡顿)
把编辑器重构为自包含 `@st.fragment`:
- 覆盖范围:画布+右侧框列表+撤销/保存+通过/拒绝+翻页导航(一个图片编辑单元);
- 删/撤销处理改 `st.rerun(scope="fragment")` —— 只重跑编辑器,页面其余不动;
- **保存/通过逻辑必须移入 fragment**(fragment 内按钮点击只触发 fragment 重跑,不会执行外部调用方代码——这是重构的硬性原因);宿主(tab2 review_ui / tab3 两种模式)只传 img、初始 boxes、names、kp、持久化回调(写 txt / 写 review_state / 通过拒绝);
- 模型驱动数据流、pending 删除表、空回传保护等既有逻辑保持不变;
- Streamlit 1.63 支持 st.fragment(1.37+ 稳定)。

## 第 3 步:回归验证
- py_compile + test_annotate.py 单测 + AppTest 三 tab 零异常;
- 浏览器实测:双标记(iframe+侧栏元素)跨删除存活;翻页/自动保存/通过落盘正常;类别选择不串;
- 重启服务,交给用户在实际页面复验手感。

## 回退
若 fragment 与 st_canvas 渲染不兼容(出现异常/空白),回退到第 1 步验证通过的状态:闪屏已消除,仅保留全页重跑的轻微延迟,不劣于现状。
