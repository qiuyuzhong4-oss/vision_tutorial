  - 安装 Python 3.10+，执行：

  py -m pip install -r requirements.txt

  - 把 config.yaml 的 Linux 路径改成 Windows 路径，建议用正斜杠：

  storage:

  libraries:
    - id: anime
      name: "动漫"

  /home/liantian/视频/动漫/剧名/第1集.mp4

  D:/影视/动漫/剧名/第1集.mp4

  anime + 剧名/第1集.mp4

› 如果是安卓端呢


• 安卓端不能直接复制运行，因为涉及 Android 的沙盒存储权限、后台任务和播放器接
  口。不过现有搜索、剧集管理、YAML 数据结构和界面设计仍可借鉴。

  最推荐的安卓方案是：

   功能        安卓实现
  ━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   播放器      Jetpack Media3 / ExoPlayer
  ──────────  ────────────────────────────────────
   目录选择    Storage Access Framework（SAF）
  ──────────  ────────────────────────────────────
   观看进度    Room SQLite
  ──────────  ────────────────────────────────────
   后台下载    WorkManager + 前台通知
  ──────────  ────────────────────────────────────
   配置        应用内目录选择，支持导入/导出 YAML
  ──────────  ────────────────────────────────────
   格式转换    尽量放在电脑端，安卓只负责播放

  你现在的 27 个视频都是 MP4，很适合 Media3。播放器在暂停、每隔几秒和应用进入后
  台时保存 currentPosition，打开时调用 seekTo() 恢复即可。

  安卓不能稳定使用这种普通路径：

  path: "/storage/emulated/0/Movies/"

  现代 Android 应通过系统目录选择器获得类似这样的授权地址：

  content://com.android.externalstorage.documents/tree/primary%3AMovies

  所以 YAML 可以继续保留，但目录最好由应用内“添加媒体库”按钮选择，然后导出为
  YAML；不建议让用户手写 Android 路径。

  有三条实现路线：

  1. 原生 Android，最推荐
     Kotlin + Jetpack Compose + Media3。性能、后台下载、遥控器、字幕和硬件解码体
     验最好。可以参考 Next Player 这类 Media3 开源项目。

  2. Capacitor/WebView 混合应用
     复用你现在大部分 HTML/CSS/JS 界面，安卓原生层负责目录扫描、Media3 播放、
     SQLite 和下载。开发量比完全重写小，也能打包 APK。这个最符合你“同一个工作台
     多端使用”的方向。

  3. 手机连接电脑工作台
     视频仍放电脑，安卓浏览器通过局域网打开电脑工作台。这种改动最少，但需要给当
     前服务增加登录令牌和访问控制，不能简单地把 127.0.0.1 改成 0.0.0.0 就直接暴
     露。

  不建议在正式安卓应用里运行 Flask/Python。Termux 确实能勉强运行，但容易被系统清
  理，目录权限、FFmpeg、启动方式都比较麻烦。

  如果以后 Linux、Windows、Android 都要支持，我建议最终采用：

  共享 Web 前端
  ├── Linux/Windows：Flask + Chromium 应用窗口
  └── Android：Capacitor + Kotlin 原生桥
      ├── Media3 播放
      ├── SAF 扫描目录
      ├── Room 保存进度
      └── WorkManager 下载

  同时应尽快把进度 ID 改成“媒体库 ID + 相对路径”，这样电脑和安卓才能迁移或同步观
  看记录。
