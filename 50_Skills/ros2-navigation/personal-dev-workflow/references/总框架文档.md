# 工作台 · 框架文档

## 1. 项目定位（一句话）
个人开发流程固定化工作台：通过 Web 界面 + 一键启动脚本，把「需求梳理 → AI 讨论完善 → 文档固化 → 标准目录生成 → 编码准备」整条链路固化下来。

## 2. 推荐可借鉴项目 / 技术选型方向
（当前阶段仅作框架级参考，后续可在《技术链路文档》中细化）

| 方向 | 可借鉴思路 | 备注 |
|------|------------|------|
| 本地 Web 工作台 | VS Code Web、Obsidian、Logseq、SiYuan | 轻量、本地优先、可自定义背景 |
| 项目脚手架生成 | cookiecutter、yeoman、create-react-app 类工具 | 固定目录 + 可自定义主目录名 |
| 文档拖拽放置 | 现代文件管理器 + Web File System Access API | 支持拖放后光标定位放置 |
| 启动脚本 | 常见开源项目的 `start.sh` / `run.sh` | 一键启动前后端 |
| 灵感记录 | Notion 快捷新建、Obsidian QuickAdd | 自定义文件名即可 |

**推荐技术栈（框架级）**：
- 前端：轻量 Web（HTML/CSS/JS 或 Vue/React + 简单 UI）
- 后端：可选本地 Node.js / Python FastAPI（当前阶段可先纯前端 + 本地文件操作）
- 启动：Bash 脚本（`.sh`）
- 文件操作：支持拖拽上传 + 本地目录读写
- 背景：CSS 自定义背景图 + 默认背景板

## 3. 整体目录结构（固定部分 + 用户自定义主目录）

```
{用户自定义主项目名}/                    # 由用户在新建时命名
├── docs/                               # 总文档目录（不常修改）
│   ├── requirements/                   # 总需求文档
│   │   └── 工作台需求总文档.md
│   ├── framework/                      # 框架文档（本文件）
│   │   └── 工作台框架文档.md
│   └── tech-chain/                     # 总技术链路文档
│       └── 工作台技术链路文档.md
│
├── requirements/                       # 单次开发需求文档目录
│   ├── image_base/                     # 截图存放
│   └── single
  		└──	{日期或功能名}_需求.md						# 单次开发需求文档目录{
  	└── archive
  		└──	(第一版讨论需求.md)	(第二版润色前.md)	(v1.0_需求冻结.md)
							#历史版本 / 原始讨论稿
│
├── rules/                              # 规则文档目录
│   └── （放置协定规则文档）
│
├── bugs/                               # 修 Bug 文档目录
│   ├── image_base/                     # 每次 Bug 的截图
│   └── {日期或Bug名}_bug.md            # 内容必须包含：
│                                       # 1. Bug 报错原因
│                                       # 2. 修复手法 / 解决方案
│                                       # 3. 相关截图（放在同目录 image_base/）
│
├── ideas/                              # 灵光一闪目录
│   └── {用户自定义文件名}.md           # 应对策略 / 便捷工具想法
│
├── scripts/                            # 启动脚本目录
│   └── start.sh                        # 工作台启动接口
│   └── （其他辅助 sh）
│
├── src/ 或 web/                        # 工作台实际代码（可选分层）
│   ├── frontend/                       # Web 页面
│   └── backend/                        # 如有本地服务
│
├── assets/                             # 静态资源
│   └── backgrounds/                    # 默认 + 自定义背景图
│
└── README.md                           # 最简 README（启动阶段）
```

**说明**：
- 括号前的目录名（`docs/`、`requirements/`、`rules/`、`bugs/`、`ideas/`、`scripts/`）为**固定命名**，不轻易变更。
- 主项目根目录名由你在「新建项目」时自行命名。
- 总文档（需求 / 框架 / 技术链路）统一放在 `docs/` 下，方便长期维护且不常改。

## 4. 各目录放置类型说明（默认只读，可通过「修改放置类型」接口更改）

| 目录 | 默认应放置内容 | 说明 |
|------|----------------|------|
| `docs/requirements/` | 总需求文档 | 使用场景、问题、接口、阶段性目标、最终目标 |
| `docs/framework/` | 框架文档 | 本文件，描述目录结构与文件职责 |
| `docs/tech-chain/` | 总技术链路文档 | 详细实现方案（如相机定位与九宫格判断等完整链路） |
| `requirements/` | 每次开发的需求文档 + `image_base/` 截图 | 单次迭代使用 |
| `rules/` | 协定规则文档 | 工作流中的强制/推荐规则 |
| `bugs/` | 修 Bug 记录文档 | 问题描述、复现、修复方案 |
| `ideas/` | 灵光一闪想法 | 用户自定义文件名，记录策略或工具构想 |
| `scripts/` | `.sh` 启动与辅助脚本 | 必须包含 `start.sh` 作为工作台启动接口 |
| `assets/backgrounds/` | 背景图片 | 默认背景板 + 用户上传的自定义背景 |

## 5. 核心接口与页面结构（框架级）

### 5.1 启动接口
- 文件：`scripts/start.sh`
- 功能：一键启动工作台 Web 页面（及可选本地服务）
- 要求：启动简便，路径短

### 5.2 Web 页面主要模块
1. **首页 / 工作台主界面**
   - 自定义背景 + 默认背景板切换
   - 灵光一闪入口（命名后保存到 `ideas/`）
   - 新建项目入口
2. **新建项目流程**
   - 输入主项目目录名
   - 自动生成上述固定目录结构
   - 生成后弹出「各目录应放置文档类型」提醒
3. **文档拖放区域**
   - 支持拖动文件，最终光标位置即为放置目标位置
4. **提醒 / 引导面板**
   - 新建时：提醒初始需求文档必填项
   - 准备写代码时：提醒是否先写最简 README 及写法
   - 日常：提醒更新规则文档
5. **设置**
   - 修改各目录「放置类型」描述（默认只读，点修改后可编辑）
   - 背景上传 / 恢复默认

### 5.3 灵光一闪接口
- 入口：Web 表单或快捷按钮
- 行为：用户输入自定义文件名 → 保存为 `ideas/{自定义名}.md`

## 6. 流程与提醒节点（框架级映射）

| 阶段 | 工作台行为 |
|------|------------|
| 新建项目 | 生成固定目录 → 提醒初始需求文档必填内容 |
| 需求完善 | 引导「草稿 → 外部 AI 讨论 → 规范需求 → 复述确认 → 生成开发文档」 |
| 结构生成后 | 展示各目录应放文档类型（可修改） |
| 准备让 AI 写代码 | 提醒是否先写最简 README，并给出分阶段写法 |
| 日常 | 提醒放置/更新规则文档 |

## 7. README 约定（与需求文档保持一致）

- **项目刚启动**：最简 README（标题 + 一句话描述 + 安装/启动命令 + 「详细需求见 docs/requirements/…，开发文档见 docs/framework/…」）
- **功能相对稳定**：补充使用说明、配置项、常见问题
- **准备交付/开源**：再打磨（截图、示例、贡献指南）

README 与需求文档、框架文档、技术链路文档职责分离，不互相替代。
