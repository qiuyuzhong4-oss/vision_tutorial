

# 工作台需求文档（初稿）

## 1. 项目概述

工作台是一个面向个人开发流程的辅助系统，用于将「需求分析 → AI 讨论完善 → 文档固化 → 项目结构生成 → 启动与灵感记录」的完整工作流固定下来，减少随意性和上下文混乱，提升每次启动新项目时的规范性和效率。

## 2. 使用场景

1. **新建项目前**：需要快速创建标准化项目骨架，并被提醒初始需求文档应包含的内容。
2. **需求梳理阶段**：通过工作台引导，先写使用场景、问题、接口、阶段性目标与最终目标，再借助外部 AI（Grok、智谱等）讨论完善，避免直接在本地终端开启编码。
3. **文档管理阶段**：需要统一管理总需求文档、框架文档、技术链路文档、单次开发需求、截图、规则文档、修 Bug 文档。
4. **日常开发中**：需要一键启动工作台、自定义背景、快速记录「灵光一闪」想法（应对策略或便捷工具构想）。
5. **准备写代码前**：需要被提醒是否先写最简 README，以及 README 的分阶段写法。

## 3. 要解决的问题

- 开发前容易跳过完善需求，直接让本地 AI 写代码，导致上下文脏乱、需求不清晰。
- 需求文档、开发文档、技术实现链路混在一起，后期难以维护和回溯。
- 每次新建项目时目录结构、文档放置规则不统一，需要反复手动创建。
- 灵感（策略、工具想法）没有固定记录入口，容易丢失。
- 启动工作台不够简便，缺乏统一的启动接口和可视化界面。
- README 与需求/开发文档职责不清，容易写得过早或过晚。

## 4. 核心功能需求

### 4.1 工作台基础能力
- 提供完整的 Web 页面作为主要交互界面。
- 启动必须简便，提供 `.sh` 启动脚本接口。
- 支持自定义背景图片，同时提供默认背景板。
- 提供「灵光一闪」记录接口，用户可自行命名 idea 文件（通常用于记录应对策略或便捷工具开发想法）。
- 放需要提前放的文档要支持拖动放置,我最后光标放在那里就是这个我拖动的文件需要放置的位置,

### 4.2 项目结构与文档管理
- 新建项目时自动生成固定目录结构（目录名采用市面常用命名），主项目目录名由用户自定义。
- 固定目录包括：
  - 规则文档目录
  - 启动脚本（`.sh`）目录
  - 需求文档目录（存放每次开发的需求文档 + 截图 `image_base`）
  - 总文档目录（总需求文档 + 总开发文档/框架文档 + 总技术链路文档，三者为总文档，不常修改）
  - 修 Bug 文档目录,(存放每次bug报错的原因,修bug的手法,+截图image_base)
  - 灵感（ideas）目录
- 生成结构后，工作台需提醒每个目录应放置的文档类型。
- 目录放置类型描述默认只读，用户可通过「修改放置类型」接口进行更改并保存。

### 4.3 流程引导与提醒
- **新建项目时**：提醒初始需求文档必须包含的内容（使用场景、解决的问题、接口定义、阶段性目标、最终目标）。
- **需求完善阶段**：引导用户先写草稿开发文档 → 与外部 AI 讨论可借鉴项目 → 完善需求 → 让 AI 输出规范需求文档 → 让 AI 复述需求确认 → 再生成开发文档（含框架与技术链路）。
- **开发文档要求**：
  - 建议借鉴的项目
  - 技术链
  - 项目框架（具体到文件夹放置什么文件，方案名称可直接附在框架文件夹名旁）
  - 详细技术实现链路单独成文（例如相机定位与九宫格空位判断的完整实现路径）
- **准备让 AI 写代码时**：提醒是否需要先写 README，并给出分阶段写法建议。
- **日常**：提醒放置与更新规则文档。

### 4.4 README 相关约定
- 项目刚启动时：写最简 README（标题 + 一句话描述 + 安装/启动命令 + 详细需求与开发文档的传送路径）。
- 功能相对稳定时：补充使用说明、配置项、常见问题。
- 准备交付/开源时：再打磨（截图、更清晰示例、贡献指南等）。
- README 与需求文档、开发文档职责分离，不互相替代。

## 5. 接口定义（初步）

| 接口类型       | 说明                                   | 形式          |
|----------------|----------------------------------------|---------------|
| 启动接口       | 一键启动工作台                         | `.sh` 脚本    |
| 新建项目接口   | 生成固定目录结构 + 主目录命名          | Web 操作      |
| 灵光一闪接口   | 记录灵感，支持自定义文件名             | Web 表单/按钮 |
| 修改放置类型接口 | 编辑各目录应放文档类型的描述         | Web 操作      |
| 提醒/引导接口  | 在关键节点弹出或展示提醒内容           | Web 页面提示  |
| 背景设置接口   | 上传自定义背景 / 恢复默认背景          | Web 设置      |

（后续可补充更细的 API 或页面路由定义）

## 6. 阶段性目标

1. **第一阶段**：实现工作台基础 Web 页面、启动 `.sh`、自定义/默认背景、灵光一闪记录功能。
2. **第二阶段**：实现新建项目时自动生成固定目录结构，并完成各目录放置类型的默认提示与可修改机制。
3. **第三阶段**：完善流程引导与关键节点提醒（需求文档必填项、README 提醒、规则文档提醒等）。
4. **第四阶段**：优化与外部 AI 讨论的辅助流程（模板导出、文档导入等），并完善总文档与单次文档的管理体验。

## 7. 最终目标

建成一个「启动即规范」的个人开发工作台：  
打开即可按固定流程走完「需求 → AI 完善 → 文档固化 → 结构生成 → 编码准备」，同时提供轻量灵感记录与美观可定制的界面，让每次新项目都从清晰、可追溯的文档和结构开始，而不是从临时对话和散乱文件开始。

## 8. 非功能需求（补充）

- 启动速度快，操作路径短。
- 界面简洁，重点信息（提醒、目录说明）突出。
- 文档与目录结构长期稳定，不轻易变更核心命名。
- 支持后续扩展（更多模板、更多提醒节点、与本地/云端 AI 更深度集成）。
