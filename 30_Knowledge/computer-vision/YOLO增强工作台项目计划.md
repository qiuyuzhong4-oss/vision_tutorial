# YOLO 数据增强工作台 项目计划

> 来源:从 [yolo资料及后续的idea.md](yolo资料及后续的idea.md) 中与 Grok 的讨论提炼
> 日期:2026-09-16

---

## 一、项目动机(我为什么想做这个)

1. **查文档太麻烦**:我平时用 Ultralytics 训练时,每次都是查资料后设置参数去调用它内置的增强函数(hsv、degrees、mosaic、mixup 等),参数多、记不住,反复查文档效率低。
2. **调参看不到效果**:增强参数之间互相影响,改完参数后很难直观知道"对**我自己的数据集**实际增强出来是什么样子",只能靠训练结果间接验证,试错成本高。
3. **标注流程繁琐**:想用"先人工标一部分 → 预训练一个小模型 → 自动标注剩下的图片 → 人工审核"的伪标签流程来简化标注,目前没有顺手的本地工具。
4. **市场空白**:现有的中文训练可视化工具(如 YoloTrainingVisualizationPlatform、yologui 等)主要做训练参数配置和训练监控,对数据增强的实时预览支持很弱;官方的 Ray Tune 是黑盒自动搜索,不是人工可控的可视化工作台。**"增强参数选择 + 实时预览 + 配置导出 + 半自动标注"这个组合目前基本是空白。**

**定位**:轻量的本地数据准备工具,**专注增强调参预览 + 半自动标注**,不做重型训练平台(差异化恰恰在于专注)。

---

## 二、核心想法(两个模块)

### 模块 A:增强参数可视化工作台
上传自己的真实图片 → 左侧滑块调参数 → 右侧实时看到增强效果 → 一键导出可直接使用的训练配置。

### 模块 B:半自动标注(伪标签)
人工标注种子集 → 快速训练初始小模型 → 对未标注图片推理生成标签 → 可视化人工审核 → 导出标准 YOLO 数据集。

两个模块合起来形成完整的数据闭环:

```
数据准备 → 增强调参 → 半自动标注 → 再训练
```

### 硬件适配(本机 RTX 5060 Laptop 8GB)

- 5060 是 Blackwell 架构(sm_120),**必须 torch cu128+ 构建**,cu126 会报 no kernel image
- **"有时连不上"做成分层诊断**(驱动层 nvidia-smi / 构建层 torch / 运行层显存),各层给明确修复提示,而不是笼统报错
- 训练启动前**驱动探活带重试**(应对瞬时掉卡),失败自动降级 CPU 并提示
- 8GB 显存约束:batch=-1 自适应,imgsz 1280 时 batch 4~8

## 三、功能列表

### P0 — MVP 必做

| # | 功能 | 说明 |
|---|------|------|
| 1 | 实时预览 | 上传 1~6 张本地图片,左侧参数滑块,右侧实时显示增强效果;支持单图预览与伪 Mosaic(固定用当前上传的几张图拼接)切换;原图/增强后对比 |
| 2 | 参数分类面板 | 颜色类:hsv_h / hsv_s / hsv_v;几何类:degrees / translate / scale / shear / perspective;翻转:fliplr / flipud;高级:mosaic / mixup / cutmix / copy_paste / close_mosaic。每个参数显示**默认值、推荐范围、简短说明** |
| 3 | 一键导出配置 | 生成可直接复制的 `yolo detect train ...` 完整命令;生成 YAML 配置文件下载;保存/加载自定义预设(本地 JSON) |

### P1 — 高价值增强

| # | 功能 | 说明 |
|---|------|------|
| 4 | 场景预设一键切换 | 小目标增强、航拍/俯视、夜间/低光照、工业检测、通用默认等 |
| 5 | 多图批量预览 | 一次看 4~6 张图的增强效果 |
| 6 | **半自动标注模块(单独标签页)** | 见下方详细流程 |
| 7 | Albumentations 自定义 | 高级用户可追加模糊、噪声、CLAHE 等官方没有的变换 |
| 8 | 参数重置 / 随机一键试探 | 快速探索参数空间 |

**半自动标注模块(P1-6)流程:**

1. 种子集选择:指定已人工标注的文件夹(建议 100~500 张,类别尽量覆盖、边界标紧)
2. 快速训练:一键用种子集训一个小模型(可选 n/s、epochs、imgsz)
3. 推理生成标签:对未标注目录跑 `model.predict(save_txt=True, conf=阈值)`,置信度阈值用滑块控制,默认建议 0.7(宁可漏标,不要大量错框)
4. 预览模式:先跑几张看效果,满意再批量处理
5. **人工审核界面(必须)**:图片 + 预测框可视化,支持删除错误框、修正类别、补标漏检
6. 导出:审核通过的标签生成标准 YOLO 数据集结构(images + labels)

进阶可选:多轮迭代(标完一批→重训→再标下一批)、结合 SAM 做分割(官方 auto_annotate)、不确定性采样(优先审核模型最没把握的图片)。

### P2 — 进阶(可选)

- 增强后目标尺寸分布统计(判断小目标是否被过度缩小)
- 导出离线增强数据集(图片 + 标签)
- 历史配置对比

## 四、技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 界面 | **Streamlit**(首选)或 Gradio | 开发最快,Python 全栈,滑块 + 图片预览天然支持;Streamlit 布局更自由适合做正式小工具,Gradio 上手更快方便分享链接 |
| 增强核心 | **Ultralytics `data.augment`(v8_transforms)** + Albumentations | 直接复用官方变换,保证预览和真实训练**完全一致** |
| 部署 | 本地运行(可选后期打包 exe / Electron + FastAPI) | 个人与小团队足够,前期不做桌面化 |

---

## 五、关键技术要点(实现时必看)

1. **不要自己重写增强逻辑**:真正与训练一致的预览必须直接复用 `ultralytics.data.augment.v8_transforms` / `Mosaic`、`RandomPerspective`、`RandomHSV`、`RandomFlip`、`LetterBox`、`Compose` 等,而不是用 OpenCV 手写近似版本。第一周可先用简化版跑通 UI,但最终必须切到官方变换。
2. **官方 transform 的输入格式适配**:官方变换需要特定的 labels 结构(含 bbox),预览时需构造适配层——这是主要的工程量所在。
3. **bbox 必须同步变换并画出来**:否则用户看不到增强对目标框的影响,预览就失去意义。
4. **Mosaic/MixUp 预览做"伪预览"**:固定用当前上传的几张图拼接,保证可复现、可对照。
5. **伪标签绝不能全自动信任**:必须有人工审核环节,否则错误标签会污染后续训练;审核时重点看小目标、遮挡、边缘情况;第一轮建议用较高置信度阈值。
6. **训练分辨率匹配**:工作台的预览 imgsz 应与用户最终部署时相机取流后实际输入尺寸一致(这是我在讨论中确认过的结论:训练 imgsz 尽量接近部署输入,推理时用与训练相同的 imgsz 效果最佳)。

## 七、风险与注意事项

- **官方 transform 适配工作量**:labels 结构适配是最大工程点,预留缓冲时间。
- **伪标签质量依赖种子集**:种子集类别覆盖不全、边界标得不紧,会让自动标注系统性出错;工具里应提示种子集质量要求。
- **不要越做越重**:警惕滑向"完整训练平台",保持"增强调参 + 预览 + 配置导出 + 半自动标注"的专注边界,这是与现有工具的差异化所在。
- **实时性**:滑块拖动时每张图都要跑一遍变换管道,注意缓存与图片尺寸限制,避免卡顿。

## 八、背景知识沉淀(讨论中确认的结论,与本项目相关)

这些是我在讨论中问过并确认的知识点,作为工作台设计的依据(详细内容见原文档):

1. **模型大小的行业标准衡量**:参数量(Params/M,类比 LLM 的 B)、FLOPs/GFLOPs、模型文件大小(MB)、输入分辨率,以及 mAP@0.5 / mAP@0.5:0.95 / Latency。训练数据量和类别数不决定模型大小,架构才决定。
2. **同一模型 + 同一输入分辨率下,图片里有目标/没目标的计算量与功耗基本一致**(全卷积网络前向计算量只由输入尺寸和网络结构决定);只有改模型大小(n→s)、分辨率、精度(FP32→INT8)、batch size 或硬件频率,功耗才明显变化。
3. **量化两条路**:QAT(训练时量化感知,`train` 时 `quantize=8`,精度损失更小)优于 PTQ(训练后量化导出,`model.export(format="engine", quantize=8, data=...)`,需校准数据);训练默认 `amp=True` 是 FP16 混合精度。
4. **部署省资源手段**(已训练模型可用):量化 → TensorRT/对应硬件引擎导出(最快见效)、结构化剪枝、知识蒸馏、降低输入分辨率,组合可达 2~4 倍加速。
5. **精度提升主要靠数据侧**:标注贴紧边界、标签准确、模拟现场(光照/横竖斜摆放);官方内置增强没有真正的 roll/pitch/yaw 三维旋转(degrees 只是 2D 旋转,perspective 只是轻微透视),需要 Albumentations 或离线脚本自实现。
6. **小目标/远距离方案**(这也是工作台"小目标增强预设"的依据):数据侧补远距离样本、Copy-Reduce-Paste、提高 imgsz;推理侧 SAHI 切片推理(最推荐、无需重训)、两阶段 ROI(粗检测/颜色先验 → 裁剪放大 → 二次 YOLO,实时性会降)。
